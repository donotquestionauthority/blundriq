# 001 — No Syzygy tablebase anywhere

**Decision (2026-09-19).** The system has no endgame tablebase: not on the API host, not in the pipeline, not in the Actions cache.

**Why.** The previous system used a 3–5-man Syzygy set for endgame drilling (API host, paid persistent disk) and as the first rung of Review's expected-score ladder (pipeline, 400 MB cached on Actions). Drilling is dropped. Rob's focus is openings; the tablebase only makes Review's pricing of 3–5-man endgames exact.

**Consequence.** `core/review` prices every position by forced mate, then the engine eval through a win-probability curve. In a game that reaches a castling-free ≤5-man position this can change event existence, anchor, cost, and game-wide fields (`peak_es`, `game_priced_loss`) relative to the old detector; in other games nothing changes. Review events are therefore regenerated by the new detector, never migrated. The `endgame_technique` route stays, decided by material count. The "Convert the win" / "Hold the draw" tiles and the endgame aggregates behind them do not exist here.

**If it is ever wanted back.** The rung-1 code is in the old repository's `review_core.py` under the `pre-personal-rebuild` tag.
